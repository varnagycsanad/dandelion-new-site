## Cel

Ez a contract a DWA elorehaladasat es tovabbengedhetoseget negy allapotban irja le, hogy a DCA kesobb konzisztensen tudja ertekelni a honlapos feladatok release- vagy implementacios keszenletet.

## Readiness statuses

### `READY`

A feladat vedhetoen tovabbengedheto, mert:

- a scope tiszta es DWA-hatoskoru,
- az ownership routing tiszta,
- nincs nyitott DMA/DSA/DCA hard dependency,
- ha volt publikus frontend valtozas, a `npm run build` sikeres,
- a CTA es tracking contract ertelmezheto,
- nincs secret, `dist/` vagy platform-write keveredes.

### `READY_WITH_WARNINGS`

A feladat alapvetoen tovabbengedheto, de dokumentalandok maradnak olyan kockazatok, amelyek nem blokkoljak a DWA altal vedheto site-oldali outputot.

Tipikus esetek:

- kulso platformvalidacio nem tortent, de nem is volt scope-ban,
- image vagy SEO draft emberi reviewra var,
- vannak nem ellenorzott, de nem release-blockolo kulso feltetelek,
- a build sikeres, de maradt ismert, nem a jelen taskbol szarmazo warning.

### `HOLD_REVALIDATION_REQUIRED`

A tovabblepeshez ujraellenorzes vagy kulso specialist input kell, mielott a DCA vedheto release- vagy implementacios dontest hozhatna.

Tipikus esetek:

- a brief hianyos vagy pontositast igenyel,
- booking truth vagy kampanytracking elvaras nincs megerositve,
- a DWA site-oldali terve megvan, de DMA vagy DSA validacio nelkul nem vedheto a vegso kimenet,
- buildet kellene futtatni, de a tenyleges frontend diff meg nem vegleges.

### `BLOCKED_NO_DEFENSIBLE_RELEASE`

A feladat jelen allapotban nem engedheto tovabb, mert nem lehet vedheto release- vagy implementacios allitast adni.

Tipikus esetek:

- tiltott platformmuvelet vagy secret-erintes kerul a scope-ba,
- `dist/` szerkesztessel akarjak megoldani a valtozast,
- DSA nelkul booking vagy Sabee truthot kellene allitani,
- a build megbukik egy jelen task altal okozott hiba miatt,
- ownership conflict vagy approval hiany miatt nincs vedheto tovabblepes.

## Kotelezo ellenorzesek

### 1. Git status

Kotelezo:

- `git status --short`

Cel:

- legyen lathato, hogy mi az elo repo-allapot,
- ne keveredjen a taskhoz nem tartozo publikus vagy marketing valtozas a DWA outputba.

### 2. Scope

Ellenorizni kell:

- pontosan mely route, oldal, komponens, data fajl vagy dokumentacios contract erintett,
- DWA-hatoskoru-e a kert valtozas,
- nincs-e briefen tuli scope-bovites.

### 3. Ownership routing

Ellenorizni kell:

- mi marad DWA,
- mi DMA,
- mi DSA,
- mi DCA approval vagy release gate.

Ha ez nem tiszta, a legmagasabb vedheto allapot legfeljebb `HOLD_REVALIDATION_REQUIRED`.

### 4. Build requirement

Szabaly:

- ha nincs publikus frontend kodvaltozas, build nem kotelezo,
- ha van publikus frontend valtozas, `npm run build` kotelezo,
- ha deploy/check reteg is erintett, `npm run check` kotelezo.

Build nelkuli publikus frontend valtozas nem lehet `READY`.

### 5. CTA safety

Ellenorizni kell:

- a CTA szoveg, irany es szerep vedheto-e,
- exploratory es booking CTA nem mosodik-e ossze,
- booking allitas vagy IBE link nem lep-e at DSA truth teruletere.

### 6. Tracking contract

Ellenorizni kell:

- a feladat csak site-side event contractot erint-e,
- nincs-e GTM/GA4 remote publish vagy admin igeny,
- a CTA event semantika ertelmezheto-e.

### 7. Image workflow

Ellenorizni kell:

- a kepigeny `src/assets` es registry iranyba mutat-e,
- nincs-e legacy runtime vagy `dist`-szintu kezi kepbekotes,
- AI alt/title/caption draft nem lesz-e automatikusan final truth.

### 8. SEO / GEO

Ellenorizni kell:

- title, meta description, H1, canonical, schema, internal linking vagy lokalizacio erintettseget,
- az esetleges SEO/GEO allitas site-side marad-e,
- nincs-e platform-admin scope-eltolas.

### 9. DSA / DMA / DCA escalation

Ellenorizni kell:

- kell-e DSA booking validacio,
- kell-e DMA kampany vagy tracking approval,
- kell-e DCA release, ownership vagy approval dontes.

## Status decision matrix

| Helyzet | Eredmeny |
|---|---|
| Dokumentacios vagy contract task, nincs tiltott erintes, nincs buildszukseglet | `READY` |
| Publikus frontend valtozas, build sikeres, kulso platformvalidacio nem scope | `READY_WITH_WARNINGS` vagy `READY` a warnings fugvenyeben |
| Site-side terv kesz, de DMA vagy DSA megerosites hianyzik | `HOLD_REVALIDATION_REQUIRED` |
| Tiltott platformmuvelet, secret-erintes, `dist` edit vagy vedhetetlen booking claim kerul be | `BLOCKED_NO_DEFENSIBLE_RELEASE` |
| Publikus frontend diff van, de nincs build | legfeljebb `HOLD_REVALIDATION_REQUIRED` |
| Publikus frontend diff van es a build a valtozas miatt elbukik | `BLOCKED_NO_DEFENSIBLE_RELEASE` |

## DCA output schema

A DWA a DCA fele minimum ezt a strukturat adja:

```md
## DWA preflight output
- Readiness status:
- Scope:
- Ownership routing:
- Build requirement / result:
- CTA safety:
- Tracking contract:
- Image workflow:
- SEO / GEO:
- Warnings:
- Required escalations:
- Blocking conditions:
```

## Interpretation guardrails

- `READY` nem jelent automatikus kampanyinditasi vagy platform publish jovahagyast.
- `READY_WITH_WARNINGS` csak akkor vedheto, ha a warningok nem ownership- vagy buildkritikusak.
- `HOLD_REVALIDATION_REQUIRED` nem bukas, hanem vedelmi allapot.
- `BLOCKED_NO_DEFENSIBLE_RELEASE` eseten a DWA nem probalhatja meg "kis magyarazattal" megis tovabbengedni a feladatot.

## Operational note

Ez a contract a DCA kesobbi preflight modulja szamara keszult. A negy statusz es a kotelezo ellenorzesek olyan minimalis struktura, amely a jelenlegi repo dokumentacios allapotabol is vedhetoen levezetheto.
