## Cel

Ez a terv azt rogizti, hogyan kell a DCA projektben kesobb bekotni a `dandelion-website-agent` specialistat ugy, hogy a DWA vilagosan kulonvaljon a DMA-tol es a DSA-tol, de a Control Center tovabbra is egyseges intake, routing, preflight es executive-output reteget adjon.

Ez a dokumentum nem modositja a DCA repo-t. A DCA oldali konkret fajlneveket es pathokat a masik repo-ban ellenorizni kell. Az alabbi lista a logikai fajlcsoportokat es elvart mezoket irja le.

## 1. DCA-ban erintett registry es domain fajlcsoportok

A DCA oldalon minimum az alabbi logikai reteghez kell majd nyulni:

### Specialist registry

Ide kell bekerulnie a DWA specialist metaadatainak:

- specialist id
- owner
- domain
- repo path
- safe capabilities
- forbidden capabilities
- required inputs
- preflight contract hivatkozas
- trust/evidence policy

Javasolt logikai target:

- specialist registry vagy `specialists` index
- domain specialist-map vagy routing-map

### Run intake schema

Ide kell bekerulnie annak a felismerese, hogy mikor honlapos feladat a bejovo keres:

- landing page
- Astro oldal
- CTA / tracking contract
- site-side SEO/GEO
- image workflow
- accommodation page vagy route-level frontend scope

Javasolt logikai target:

- intake classifier
- task-domain normalizer
- business-goal to specialist routing schema

### Routing layer

Ide kell bekerulnie a DWA mint valaszthato specialist:

- DWA-only routing
- DMA + DWA kooperacios routing
- DSA + DWA routing booking bizonytalansagnal
- DCA hold/block routing tiltott scope eseten

Javasolt logikai target:

- routing rules
- domain arbitration vagy conflict-resolution layer

### Preflight / readiness layer

Ide kell bekerulnie a DWA negyallapotu readiness modellje:

- `READY`
- `READY_WITH_WARNINGS`
- `HOLD_REVALIDATION_REQUIRED`
- `BLOCKED_NO_DEFENSIBLE_RELEASE`

Javasolt logikai target:

- preflight status enum
- release-readiness evaluator
- specialist readiness aggregator

### Trust / evidence layer

Ide kell bekerulnie a DWA evidenciaszintjeinek ertelmezese:

- `verified-repo`
- `verified-build`
- `documented-contract`
- `inferred-needs-validation`
- `forbidden-to-claim-as-verified`

Javasolt logikai target:

- trust policy
- evidence annotation schema
- executive summary confidence formatter

### Executive output layer

Ide kell bekerulnie annak a mintanak, ahogy a DCA magyar operatori kimenetet ad a DWA outputbol:

- readiness status
- scope
- build allapot
- CTA/tracking megjegyzes
- warnings
- escalation pontok

Javasolt logikai target:

- executive output formatter
- operator summary template

### Test layer

Kulon tesztek kellenek a DWA routingra es STOP viselkedesre.

Javasolt logikai target:

- routing tests
- preflight tests
- trust/evidence tests
- executive-output snapshot tests

## 3. Illeszkedes a DCA run intake retegehez

Amikor a DCA bejovo keresest kap, a DWA iranyba kell routingolnia, ha a user celja elsodlegesen:

- site-source modositas,
- landing page vagy kampanyoldal megvalositas,
- honlapos CTA vagy tracking contract valtozas,
- site-side SEO/GEO vagy lokalizacios feladat,
- asset vagy image workflow feladat.

Nem szabad tisztan DWA-ba routingolni, ha a keres valojaban:

- Ads vagy Meta platformmuvelet,
- GTM/GA4/GSC remote admin,
- Sabee pricing vagy availability igazsag,
- secret ownership vagy tokenkezeles,
- kampanybudget vagy campaign-state dontes.

## 4. Illeszkedes a DCA routing retegehez

### DWA-only

Hasznalhato, ha a feladat teljesen site-side dokumentacios vagy frontend scope.

### DWA + DMA

Kell, ha:

- landing page marketing briefre epul,
- UTM vagy tracking naming kerdes van,
- kampanyuzenethez kell oldal.

### DWA + DSA

Kell, ha:

- booking CTA vagy Sabee irany bizonytalan,
- rate plan, package vagy room mapping kerdes merul fel,
- az oldal booking truthot allit.

### DWA + DMA + DSA + DCA gate

Kell, ha:

- a landing egyszerre kampanykritikus es bookingkritikus,
- a release ownershipje tobb specialist kozott oszlik meg,
- a tovabblepeshez emberi approval kell.

## 5. Illeszkedes a DCA preflight retegehez

A DCA-nak a DWA outputbol minimum ezeket kell aggregalnia:

- volt-e `git status --short` alapu repoellenorzes,
- kellett-e build vagy check,
- mi a readiness statusz,
- van-e warnings vagy hold condition,
- kell-e DMA vagy DSA megerosites,
- maradt-e nem ellenorzott kulso igazsag.

Kulon fontos:

- a `READY` nem jelent automatikus publish-t,
- a `HOLD_REVALIDATION_REQUIRED` vedelmi allapot, nem hibaallapot,
- a `BLOCKED_NO_DEFENSIBLE_RELEASE` nem kozmetikazhato operatori optimizmussal.

## 6. Illeszkedes a DCA trust retegehez

A DCA executive outputban kulon kell valasztani:

- mit igazolt a repo,
- mit igazolt a build,
- mi csak dokumentacios contract,
- mi kulso validaciot igenyel.

Ez ved a kovetkezo hibaktol:

- booking truth ugy tunik, mintha ellenorzott lenne,
- platform publish allapot ugy hangzik, mintha a DWA bizonyitotta volna,
- warningos output tul eros operatori ajanlassa valik.

## 7. Illeszkedes az executive output retegehez

A DCA vegso operatori kimenete javasoltan tartalmazza:

- rovid magyar statuszmondat,
- mely specialist dolgozott,
- readiness allapot,
- build/status megjegyzes,
- mik a fobb kockazatok,
- mikor kell ujra DMA vagy DSA,
- mikor kell explicit DCA approval.

Peldamondat:

`A DWA site-oldali resze vedhetoen kesz, de a booking irany DSA megerositest igenyel, ezert a feladat jelenleg HOLD_REVALIDATION_REQUIRED allapotban van.`

## 8. DWA vs DMA vs DSA elvalasztas a DCA-ban

### DWA

- honlap source
- Astro implementacio
- route, CTA, site-side tracking, SEO/GEO, image workflow

### DMA

- Ads, Meta, GA4, GTM, GSC platformmuvelet
- kampanybrief
- UTM naming strategy
- platform publish/admin

### DSA

- Sabee truth
- booking engine, room mapping, package, coupon, rate plan
- availability/pricing/OTA-kockazat

### DCA

- intake
- routing
- specialistak kozi konfliktusfeloldas
- preflight aggregation
- approval gate
- executive summary

## 9. DCA-ban szukseges tesztek

Minimum javasolt tesztek:

- landing page brief DWA-ra routolodik, ha nincs platform-admin igeny
- Ads/Meta publish igeny nem routolodik tisztan DWA-ra
- booking bizonytalansag eseten DSA escalation jelenseg
- `dist` edit keresnel block statusz
- secret-erintesnel block statusz
- publikus frontend diff build nelkul nem kaphat `READY`
- `READY_WITH_WARNINGS` operatori output nem tunhet teljes release-jovahagyasnak

## 10. Javasolt kovetkezo DCA feladat

`DCA-006 - DWA specialist bekotes a Control Centerbe`

Javasolt scope:

- specialist registry bovites a DWA mezokkel,
- intake es routing szabalyok bovitese,
